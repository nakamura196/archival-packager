# ストアの更新を API で行うための設定（1 回だけ）

Microsoft ストアの申請 API を使うと、MSIX の差し替えから説明文の更新、
公開の実行までを手元のコマンドで行える。そのために **Partner Center の
アカウントを Microsoft Entra ID（旧 Azure AD）のテナントに紐づける**必要がある。
個人アカウントには既定でテナントが無いので、ここで 1 つ作る。無料。

作業は 15 分ほど。**この設定は 1 回だけ。** 以後の更新はコマンドで済む。

---

## 1. テナントを作る

1. Partner Center を開く → https://partner.microsoft.com/dashboard
2. 右上の歯車 → **アカウント設定**
3. 左の **テナント** → **Azure AD テナントの作成**
   - 会社名や組織名の欄には、ご自身の名前でよい（例: `Satoru Nakamura`）
   - ドメインは `<好きな名前>.onmicrosoft.com` の形で自動的に作られる
   - ここで作る管理者アカウント（`...@....onmicrosoft.com`）の
     **ID とパスワードを 1Password に控える**。以後 Azure portal に入るのに使う

作り終えると、Partner Center のアカウントにそのテナントが結び付く。

## 2. アプリ登録を作る

アプリ登録とは「人ではなくプログラムが Partner Center を操作するための身分証」。

1. https://portal.azure.com に、1 で作った管理者アカウントで入る
2. **Microsoft Entra ID** → **アプリの登録** → **新規登録**
   - 名前: `archival-packager-store`（何でもよい）
   - サポートされるアカウントの種類: **この組織ディレクトリのみ**
   - リダイレクト URI: 空のまま
3. 作成後の画面に出る次の 2 つを控える
   - **アプリケーション (クライアント) ID**
   - **ディレクトリ (テナント) ID**
4. 左の **証明書とシークレット** → **新しいクライアント シークレット**
   - 説明: `store-api`、有効期限: 24 か月（最長）
   - **作成直後にしか値が表示されない。** ここで 1Password に入れる
   - 期限が切れると更新できなくなる。**期限を控えておく**

## 3. Partner Center 側で権限を与える

登録しただけでは何もできない。Partner Center 側で役割を渡す。

1. Partner Center → 歯車 → **アカウント設定** → **ユーザー**
2. **Azure AD アプリケーション** のタブ → **Azure AD アプリケーションの追加**
3. 2 で作った `archival-packager-store` を選ぶ
4. 役割は **マネージャー** を選ぶ（申請の作成と公開に要る）

## 4. 1Password に入れる

項目名は `microsoft-store-api`（パレンを使わない。`op read` が壊れるため）。

| フィールド | 値 |
| --- | --- |
| `tenant_id` | ディレクトリ (テナント) ID |
| `client_id` | アプリケーション (クライアント) ID |
| `client_secret` | 2 で作ったシークレット（concealed） |
| `store_id` | `9N6XJD7THHPZ`（ストアのアドレスの末尾） |
| `secret_expires` | シークレットの期限（例: 2028-09-12） |

`.env` には値を書かず、`op://` の参照だけを置く。

---

## できること・できないこと

- **できる**: パッケージの差し替え、説明文・キーワード・スクリーンショットの変更、公開
- **できない**: アプリの新規作成と初回申請（ダッシュボードのみ）。
  0.1.0 で済んでいるので、以後は問題にならない
- **混ぜない**: ダッシュボードで作りかけの申請が残っていると、API は
  「保留中の申請がある」と言って失敗する。片方に統一する

## 403 は「権限が無い」とは限らない

続けて叩くと、**本文の空の 403** が返ることがある。2026-09-12 と 09-13 に
2 回踏んだ。いずれも直前の呼び出しは成功していて、数分置くと元に戻った。
絞り込みだと見ている。

**役割（Manager）やテナントの結び付きを疑って調べ直すと、時間を失う。**
`scripts/store_submit.py` は 403 と 429 を 60 秒・120 秒・240 秒と間を置いて
3 回までやり直し、それでも駄目なときに初めて権限を疑うよう促す。

状態を見るだけなら `--status`、資格情報だけなら `--check`。
**申請の直前に `--check` を挟まないこと。** 1 回目が通って 2 回目が 403 になる、
という形で 2 回とも踏んでいる。
