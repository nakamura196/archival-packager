最新の版は、Windows は Microsoft Store から、Mac は [GitHub のリリース](https://github.com/nakamura196/archival-packager/releases/latest)から入手できます。
入れ方は[はじめての方へ](guide/)をご覧ください。

## 0.1.9（2026-10-28）

### 主な変更

- **TIFF と PDF を、JHOVE で検査するようになりました。**
  JHOVE は、ファイルが形式の決まりどおりに作られているかを確かめる道具で、アプリに同梱しています（Java ごと入れたので、アプリが 50MB ほど大きくなりました）。
  - 変換で作った保存用の写しが検査に通らないときは、その写しを使わず、原本を保存します。
  - 原本が検査に通らないときも、原本は捨てません。警告を出し、結果を処理の記録に残します。
  - JHOVE が動かなかったときは、「検査していない」と記録し、警告を出します。「問題なし」とは扱いません。
- **SIP を作ったときの処理を、AIP まで引き継ぐようになりました。**
  ウイルス検査やファイル形式の判定などを、SIP の時点で PREMIS（処理の記録の形式）に残します。
  AIP を作るときに、その記録を日時のまま引き継ぎます。AIP を見る画面からも確かめられます。
- **SIP にも METS（パッケージの構成の目録）を作るようになりました。**
  `sip-mets.xml` として書き、AIP に引き継ぎます。AIP の METS の並び方は Archivematica と同じ形にそろえました。
- **画面の言葉を、専門の方でなくても分かるように言い換えました。**
  たとえば「識別子」は「ID（整理番号）」に、「梱包する」は「まとめる」に、「走査する」は「調べる」にしました。

### 画面

- 「資料の説明」で、必ず入れるタイトルを先頭に置き、赤字で示すようにしました。
- 中身を見るタブの名前を「資料」と「パッケージの中身」にしました。
  「資料」では、原本と保存用の写しを 1 行に並べて示します。
- 「パッケージの中身」で、CSV を表として、画像をその場で見られるようにしました。
- 「この SIP から AIP を作る」を押したあと、次に見る場所（左側の欄）を示すようにしました。
- オプションごとに説明を足しました。
- 英語の画面で、ウイルス定義の状態と、処理の記録の詳細が日本語のまま出ていたのを直しました。

### 作られるパッケージ

- 処理の記録に、ClamAV（ウイルス検査）と Siegfried（ファイル形式の判定）の版を残すようにしました。
- `accession.csv` に、名前を置き換えた後のパスも書くようにしました。
- `atom-import.csv` の資料の ID を、桁をそろえた連番（`0001` など）にしました。

### 動作環境・その他

- Mac 版は macOS 12 以降で動きます。
- アプリに入れている部品（Pillow・pypdf など）を、既知の不具合を直した版に更新しました。
  また、作るたびに部品の版が変わらないよう、版を固定して作るようにしました。
- このサイトを [https://ap.ldas.jp](https://ap.ldas.jp) に移しました。
  アプリの「このアプリについて」のリンクも新しい場所を指します。
- お問い合わせ先を nakamura.satoru@mail.u-tokyo.ac.jp に変えました。

## 0.1.8（2026-09-23）

- 処理の流れを段階ごとに図で示す「ワークフロー」タブを足しました。
- 出力先を素材フォルダの中にすると、原本のフォルダに SIP を書いてしまう不具合を直しました（いまは止めて赤字で示します）。
- SIP を作り終えたあとに「この SIP から AIP を作る」ボタンを出すようにしました。
- AIP の入力に SIP でないフォルダを選んだとき、赤字で示すようにしました。
- 英語の画面で、進み具合・警告・区分が日本語のまま出ていたのを直しました。
- [はじめての方へ](guide/)（動画つき）を公開しました。

それより前の変更は、[GitHub の履歴](https://github.com/nakamura196/archival-packager/commits/main)をご覧ください。
